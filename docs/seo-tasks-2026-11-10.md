# Dearly: SEO review and developer tasks for indexing from day one (2026-11-10)

Copy of the project doc `claude/kindly-seo-tasks-2026-11-10.md` for autopilot sessions (they can't read project docs). The chat prompts at the end of the original are replaced by `docs/autopilot/chats/21a.md` … `20r.md`; the order is in `docs/autopilot/seo-queue.md`.

Checked on `release/mvp-alpha` @ `0b4d46d` (local production build, built with `NEXT_PUBLIC_SITE_URL=http://localhost:3000`). Tool: `scripts/seo-review/audit.cjs`. It crawls every public page the way Google does (raw HTML without JavaScript, then rendered), checks robots.txt, the sitemap, canonicals, metadata, headings, structured data, Open Graph, the internal link graph, noindex on private pages and the target keywords, and runs Lighthouse (mobile) on each page.

## Verdict

The technical base is good. Every public page returns 200 with server-rendered HTML (no content needs JavaScript), has one H1, a unique title and description, a self-referencing absolute canonical and Open Graph tags. The sitemap lists only indexable pages, every private screen is noindex, trailing slashes redirect, and Lighthouse SEO is 100 on every indexed page.

What would hurt indexing at launch:
1. **One missing env var puts the placeholder domain into every canonical, the sitemap and robots.txt** (SEO-1). Nothing stops that build.
2. **The pages don't target the project's keywords where Google looks hardest**: the home H1 is the tagline, the gift page never says "elderly parent", and "AI companion for seniors" is not in any H1 (SEO-3).
3. **Too little indexable content**: 7 marketing pages, 0 articles, and 3 of the 10 target keywords have no page at all (SEO-14, SEO-15).
4. Thin or draft pages are indexed: `/waitlist` (101 words, competes with the home page) and the two "(Draft)" legal pages (SEO-4).
