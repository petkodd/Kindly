# Chat 10: Buyer funnel & account

**Autopilot notes:** branch `feature/gift-onboarding` from `origin/release/mvp-alpha`; PR into `release/mvp-alpha`. Read `docs/autopilot/README.md`, `working-agreement.md` and `decisions.md` (D2 and D7 matter here). Chats 6 and 7 are merged. Line numbers are from the 2026-10-19 audit and have drifted; find code by name. Chat 7 left two follow-ups that belong here: show email-verification status on the account page (with the existing `POST /api/auth/verify-email/resend`), and show invite / send-summary as disabled with an inline reason while the email is unverified.

GOAL: A visitor can go from the home page to a paying (or beta) gift in one clear path. A parent can never be locked out. The account page has the controls the trust page promises.

AUDIT FINDINGS:
- src/middleware.ts: NOT FOUND. Every "Set up the gift" CTA goes to /app/onboarding (content.ts). Signed out, the wizard dead-ends with "Sign in required." because a 401 is swallowed. No public page links to /signup.
- Below 1024px the header nav is `hidden lg:flex` with no menu (SiteHeader.tsx).
- The parent talk link is shown once (onboarding). There's no re-issue or revoke UI for gift parents; only self profiles get it (parent-profile page). The APIs api/parents/[id]/access-link and its /revoke already exist.
- The buyer's "Talk" nav item (AppNav.tsx) leads gift buyers to a 401.
- /invite/accept auto-POSTs on page load (InviteAccept.tsx), so email scanners accept invites.
- Onboarding: the relationship options show raw lowercase values and the "Your relationship" label is ambiguous. "Done" goes to /app/account. The memory step has no notice about storage.
- Account page: sign-out and delete have no try/catch, and the delete confirmation doesn't say what is deleted. There's no export, no billing portal and no delete-parent UI, though DELETE /api/parents/[id] exists and chat 6 added /api/me/export.
- Family summary: past weeks can't be expanded. An empty body renders a blank card. "see the note below" points to nothing.

TASKS:
1. src/middleware.ts:
   - unauthenticated /app/* (except /app/talk) redirects to /signup?next=…
   - /admin redirects to /login
   - an authenticated user on /signup or /login goes to the post-login path
   (Middleware only sees the signed cookie, not revocation — that's fine for redirects; API routes still use resolveBuyer.) Point every gift CTA to /signup?next=/app/onboarding. Handle a 401 in onboarding with router.replace. Remember signup now ends on "Check your email": carry `next` through the verification link so the buyer lands in onboarding after confirming.
2. A mobile menu below lg in SiteHeader. It must be accessible: a button with aria-expanded and a focus trap.
3. A "Parent's talk link" section on the parent profile for ALL relationship types:
   - create a new link, revoke, copy, "email it to me", and a printable large-type instruction card
   Change the buyer's "Talk" nav item to open this section instead of /app/talk.
4. InviteAccept: show who invited them and what they'll receive, with a big "Yes, send me weekly summaries" button. POST only on click.
5. Onboarding:
   - Per D2, a new "Emergency alerts" step: "If {parent} says something that sounds like an emergency, we'll text and email you right away."
     - US mobile number input, E.164 validated
     - an unticked SMS consent checkbox with TCPA-style wording (message frequency, "Reply STOP to opt out", message and data rates may apply)
     - saved to users.alert_phone and sms_alert_consent_at (the columns exist from chat 3)
     - skippable, with a warning that alerts will then go by email only
     - also editable on the account page
   - capitalised relationship labels, and the label "They are your…"
   - a storage notice on the memory step
   - "Done" goes to /app/family-summary
6. Account page:
   - "Download my data" (/api/me/export)
   - "Manage billing" through a new POST /api/billing/portal (Stripe billing portal, test mode, mocked in tests; must use resolveBuyer so the CSRF sweep test passes)
   - "Delete {parent}'s profile"
   - email verification status + "Resend link"
   - try/catch with status messages everywhere
   - the delete confirmation lists exactly what is deleted and that the subscription is cancelled
7. Family summary: expandable past weeks, a guard for an empty body, and "see the note below" either fixed or removed.
